# LEADORA — سامانه عملیات و مشتری‌یابی کسب‌وکار

سامانه وب فارسی مبتنی بر FastAPI و SQLite، قابل استقرار با Docker.

## استقرار میزبانی ابری
برای ساخت سرویس از روی مخزن GitHub، [استقرار LEADORA در Railway](https://railway.com/new?repo=gavad54/LEADORA) را باز کنید و با حساب خود وارد شوید. پیش از استفاده عملیاتی، در تنظیمات سرویس:
1. متغیر محرمانه `LEADORA_SECRET` را با یک مقدار تصادفی قوی ثبت کنید؛ آن را در مخزن یا پیام عمومی قرار ندهید.
2. یک Volume با مسیر اتصال دقیق `/data` بسازید تا پایگاه داده SQLite و نسخه‌های پشتیبان بعد از راه‌اندازی مجدد باقی بمانند.
3. سرویس را Deploy کنید و پس از ایجاد دامنه عمومی، مسیر `/api/health` را بررسی کنید.
4. در گزارش‌های سرویس مطمئن شوید وب و worker بدون خطا اجرا می‌شوند. تنظیمات مشتری‌یابی زمان‌بندی‌شده باید در پنل فعال و محدوده جست‌وجو مشخص شود.

این لینک فرایند ساخت پروژه را آغاز می‌کند؛ به‌تنهایی به معنی ایجاد حساب، تأیید هزینه، تنظیم secret/volume یا انتشار موفق نیست. قبل از تأیید هر طرح پولی، قیمت نهایی را بررسی کنید.

## قابلیت‌های موجود
- ثبت شرکت، ورود، هش امن رمز، نشست امضاشده، محدودسازی تلاش‌های ورود و جداسازی اطلاعات بر اساس شرکت.
- کالاها، مشتریان، فاکتورها، پرداخت جزئی، هزینه‌ها، فرصت‌های فروش، کمپین‌ها و داشبورد قاعده‌محور.
- واردکردن ردیف‌های CSV با گزارش خطا؛ ورود فایل سرنخ‌های کسب‌وکار با منبع و اطلاعات تماس.
- بانک جامع سرنخ‌ها با حذف/به‌روزرسانی تکراری‌ها، فیلتر نام/صنف/شهر، خروجی CSV و ثبت سابقه ورود منابع.
- جست‌وجوی کسب‌وکارهای عمومی از OpenStreetMap/Overpass و ذخیره نتایج در بانک جامع.
- تنظیمات مشتری‌یابی زمان‌بندی‌شده و worker سرور با retry/backoff، ثبت رویدادها و heartbeat سلامت.
- پیگیری داخلی سفارش‌ها و فاکتورها با تاریخچه وضعیت.
- نسخه پشتیبان JSON روی سرور، کنترل سلامت پایگاه داده و مسیرهای پشتیبان.
- رابط فارسی واکنش‌گرا، PWA، Docker Compose با volume پایدار و GitHub Actions برای آزمون Python، JavaScript و ساخت Docker.

## راه‌اندازی سریع با Docker Compose
1. فایل `.env.example` را به `.env` کپی کنید.
2. مقدار `LEADORA_SECRET` را با یک مقدار تصادفی قوی جایگزین کنید؛ نمونه ساخت:
   `python -c "import secrets; print(secrets.token_urlsafe(48))"`
3. اجرا کنید: `docker compose up -d --build`
4. سلامت: `curl http://localhost:8000/api/health`
5. لاگ وب: `docker compose logs -f leadora`؛ لاگ worker: `docker compose logs -f leadora-worker`

داده‌ها در volume پایدار `leadora_data` در مسیر `/data` نگهداری می‌شوند. برای محیط حساس، نسخه پشتیبان رمزگذاری‌شده خارج از همان سرور نیز تنظیم کنید.

راهنمای کامل‌تر: [راهنمای استقرار فارسی](DEPLOYMENT_FA.md).

## مشتری‌یابی و منابع
- برای مشتری‌یابی زمان‌بندی‌شده، در «ایجنت‌های هوشمند» مرکز محدوده، شعاع، صنف و فاصله اجرا را تنظیم کنید و worker را فعال کنید.
- worker فعلی از داده‌های عمومی OpenStreetMap استفاده می‌کند؛ اطلاعات تماس فقط وقتی موجود باشد نمایش داده می‌شود. داده‌ها کامل یا بدون خطا تضمین نمی‌شوند و نرخ درخواست محدود شده است.
- فهرست‌های مجاز شرکت‌ها/صنوف را می‌توان از CSV وارد کرد. ستون‌های پیشنهادی: `name, category, phone, website, address, city, region, latitude, longitude, source_record_id, source_url`.
- **بلد، نشان و اسنپ در حال حاضر اتصال زنده و تأییدشده ندارند.** برای هر یک API رسمی، خروجی مجاز یا قرارداد دسترسی لازم است. اطلاعات داخلی/خصوصی کاربران، رانندگان یا فروشندگان استخراج نمی‌شود.

## وضعیت انتشار و محدودیت‌ها
- GitHub Actions: [مشاهده اجراها](https://github.com/gavad54/LEADORA/actions).
- موفقیت CI ساخت Docker و آزمون کد را تأیید می‌کند؛ به‌تنهایی به معنای deploy عمومی نیست.
- استقرار واقعی به تأیید حساب میزبان، secret، volume پایدار و بررسی سلامت دامنه پس از انتشار نیاز دارد.
- ارسال پیام/تماس بازاریابی، اتصال به CRMهای بیرونی، APIهای اختصاصی نقشه‌ها و نمایشگاه‌ها، درگاه پرداخت و پورتال بیرونی طرف معامله تا زمان تنظیم اتصال و مجوزهای مربوطه فعال نیستند.
- داشبورد تحلیلی قواعدمحور است و ادعای پیش‌بینی مبتنی بر مدل آموزش‌دیده ندارد. پرداخت و اقدامات حساس بدون تأیید اجرا نمی‌شوند.

## گزارش‌های مالی LEADORA

صفحه مالی وب/PWA در مسیر `/finance` برای ثبت اسناد، ورود CSV، محاسبه گزارش‌های دوره‌ای، اصلاحیه‌ها و سوابق ممیزی استفاده می‌شود. قابلیت قرارداد مشارکت مالی مالک، محاسبه سهم مالک، داشبورد سهم و ثبت تسویه آن در PR شماره 46 بازنشسته شده‌اند؛ مسیرهای فعال و رابط کاربری مربوط حذف شده‌اند.

- ورودی‌های مالی جدید و اصلاحیه‌ها فقط با واحد `IRR` (ریال ایران) پذیرفته می‌شوند.
- گزارش دوره‌ای دارای داده تاریخی با واحد غیرریالی تا بررسی مستند و مهاجرت کنترل‌شده محاسبه مجدد نمی‌شود؛ هیچ تبدیل خودکار تومان/ریال اجرا نشده است.
- ستون‌های تاریخی مرتبط با مشارکت در پایگاه داده موجود حذف یا پاک نشده‌اند؛ خروجی API فعال آن‌ها را افشا نمی‌کند.
- واحد قیمت کالا در ساختار قدیمی محصولات ذخیره نشده است؛ بنابراین نباید پیش از بررسی داده‌های موجود، مبالغ تاریخی کالاها را ریالی فرض یا به‌صورت خودکار تبدیل کرد.
- اتصال خودکار به منابع بیرونی تا زمان پیکربندی provider، اعتبارنامه مجاز و آزمون واقعی فعال محسوب نمی‌شود.

تنظیمات مالک و ثبت رویدادهای ممیزی همچنان تحت کنترل احراز هویت سمت سرور هستند. این تغییرات در شاخه PR تا زمان ادغام و انتشار در تولید فعال نیستند.
