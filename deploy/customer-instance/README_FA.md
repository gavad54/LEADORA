# استقرار مستقل LEADORA برای هر مشتری

## اصل جداسازی

برای هر شرکت مشتری یک استقرار جداگانه ایجاد کنید؛ نه یک حساب یا tenant در استقرار مشترک. هر استقرار شامل موارد مستقل زیر است:

- سرویس وب و فرایند worker مختص همان مشتری؛
- volume اختصاصی با نام یکتای `leadora-<instance-id>-data`؛
- پایگاه داده `/data/leadora.db)، فایل‌ها، cache مجوز و پوشه پشتیبان مختص همان مشتری؛
- کلید محرمانه برنامه و تنظیمات اختصاصی؛
- دامنه، نسخه و چرخه به‌روزرسانی مستقل.

شناسه نصب باید یکتا و غیرقابل‌بازیافت باشد. دو مشتری هرگز نباید از یک `LEADORA_INSTANCE_ID`، volume، فایل `.env` یا مسیر پایگاه داده استفاده کنند. worker همان مشتری فقط volume همان مشتری را به اشتراک می‌گذارد.

## راه‌اندازی

1. برای هر مشتری یک سرور/پروژه و volume مستقل بسازید.
2. این پوشه را در یک نسخه از مخزن نگه دارید و فایل `.env.example` را به `.env` کپی کنید.
3. برای هر مشتری یک شناسه یکتا بسازید؛ نمونه موجود در فایل را عیناً برای چند مشتری تکرار نکنید.
4. برای `LEADORA_SECRET` یک مقدار تصادفی مستقل با حداقل ۳۲ نویسه در secret manager میزبان تولید کنید.
5. فقط کلید عمومی Ed25519 مرکز مجوز را در `LEADORA_LICENSE_PUBLIC_KEY` قرار دهید. کلید خصوصی امضای مجوز نباید در این استقرار، image، متغیرهای آن یا volume مشتری وجود داشته باشد.
6. پس از تأیید مسیرها و متغیرها، از همین پوشه اجرا کنید:

```bash
docker compose --env-file .env -f compose.yaml config
docker compose --env-file .env -f compose.yaml up -d --build
docker compose --env-file .env -f compose.yaml ps
```

7. سلامت همان نمونه را از مسیر `/api/health` بررسی کنید و commit، volume، دامنه و شناسه نصب را در صورت‌جلسه تحویل مشتری ثبت کنید.

## کنترل‌های امنیتی

- `app.instance_config` مسیر پایگاه داده، پشتیبان و cache مجوز را داخل volume همان مشتری محدود می‌کند.
- وجود `LEADORA_LICENSE_PRIVATE_KEY` در محیط مشتری باعث رد پیکربندی می‌شود.
- کلید عمومی فقط برای اعتبارسنجی امضای مجوز است و امکان صدور مجوز ندارد.
- نصب مشتری با فاصلهٔ زمانی قابل تنظیم (پیش‌فرض ۶ ساعت) وضعیت مجوز را از مرکز کنترل همگام می‌کند؛ اگر مرکز در دسترس نباشد، اعتبارسنجی امضای محلی و تاریخ اعتبار/grace همچنان اعمال می‌شود.
- پس از دریافت پاسخ لغو یا جایگزینی از مرکز کنترل، نمونه مشتری مجوز را در cache محلی علامت‌گذاری و مسیرهای عملیاتی را مسدود می‌کند.
- خاموشی موقت مرکز مجوز، در محدوده grace امضاشده، نباید کار عادی را قطع کند؛ پس از پایان grace مجوز منقضی است.
- فایل پشتیبان روی همان volume به‌تنهایی پشتیبان مستقل محسوب نمی‌شود؛ باید نسخه رمزگذاری‌شده خارج از میزبان و آزمون restore روی محیط جداگانه ثبت شود.
- به‌روزرسانی هر مشتری باید جداگانه، پس از backup و آزمون سازگاری همان نمونه انجام شود.

## وضعیت فعلی و محدودیت اجرایی

این قالب و اعتبارسنجی محلی، پایه استقرارهای جداگانه را فراهم می‌کند؛ اما به‌تنهایی مرکز مالک/صدور مجوز، پنل کارکنان، پرداخت و تمدید خودکار، انتقال داده امن از نصب قدیمی، پشتیبان خارج از میزبان یا استقرار واقعی چند مشتری را ایجاد نمی‌کند. تا زمان تکمیل و آزمون مرکز کنترل و اتصال اعتبارسنج مجوز به چرخه اجرای برنامه، این موارد «آماده‌سازی فنی» هستند و نه قابلیت تجاری فعال.

**هشدار:** این قالب را روی volume تولید فعلی اجرا نکنید و volume موجود را جایگزین یا حذف نکنید. مهاجرت داده فعلی فقط پس از backup مستقل و restore اثبات‌شده در محیط آزمایشی مجاز است.
