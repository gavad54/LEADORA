# مرکز کنترل مالک LEADORA

این سرویس جدا از برنامه مشتریان اجرا می‌شود و فقط اطلاعات حداقلی تجاری/عملیاتی نگه می‌دارد: شناسه نصب، شناسه مشتری، مجوز، سطح پشتیبانی، کارکنان و رویدادهای ممیزی. این سرویس volume یا پایگاه داده شرکت‌های مشتری را mount نمی‌کند و نباید به داده‌های حسابداری، مشتریان، انبار یا پرونده‌های آنان دسترسی پیش‌فرض داشته باشد.

## مسئولیت‌ها

- ثبت یک مالک اصلی؛ ورود مالک با عبارت محرمانه فارسی و کد TOTP مستقل.
- دعوت کارکنان با دامنه دسترسی محدود و قابل لغو؛ نشست‌های کارمند با غیرفعال‌سازی یا تغییر مجوز فوراً باطل می‌شوند.
- صدور مجوز Ed25519 متصل به شناسه دقیق نصب، فهرست ماژول‌ها و تاریخ اعتبار.
- لغو مجوز در مرکز کنترل؛ نمونه مشتری در همگام‌سازی بعدی وضعیت لغو را دریافت می‌کند. در حالت قطع ارتباط، مجوز تا پایان grace امضاشده قابل استفاده می‌ماند.
- ثبت قرارداد پشتیبانی و تاریخچه ممیزی.

## راه‌اندازی امن

1. این سرویس را روی پروژه/میزبان جدا از همه نصب‌های مشتری اجرا کنید.
2. از secret manager میزبان، مقادیر واقعی `.env.example` را تنظیم کنید؛ فایل `.env` را در Git قرار ندهید.
3. عبارت مالک باید فارسی، خصوصی و حداقل ۸ نویسه باشد. کد TOTP باید از برنامه احراز هویت مستقل تولید شود.
4. کلید خصوصی Ed25519 را فقط در secret manager همین مرکز کنترل قرار دهید. کلید عمومی متناظر به هر نصب مشتری داده می‌شود؛ کلید خصوصی هرگز به مشتری نمی‌رسد.
5. برای شروع:

```bash
docker compose --env-file .env -f compose.yaml config
docker compose --env-file .env -f compose.yaml up -d --build
docker compose --env-file .env -f compose.yaml ps
```

6. پس از bootstrap موفق مالک، مقدار اولیه `LEADORA_OWNER_KEYWORD` را از تنظیمات runtime حذف کنید؛ hash آن در پایگاه داده مرکز کنترل نگهداری می‌شود. `LEADORA_OWNER_MFA_SECRET` و کلید خصوصی امضا باید در secret manager باقی بمانند.

## مرز امنیتی

- پایگاه داده مرکز کنترل: `/control-data/control.sqlite3` و volume مستقل `leadora-owner-control-data`.
- پایگاه داده مشتریان در این سرویس وجود ندارد؛ هر مشتری volume جداگانه دارد.
- رمز عبارت مالک با PBKDF2 و salt تصادفی ذخیره می‌شود؛ نشست‌ها به‌صورت hash نگهداری می‌شوند.
- لغو فوری مجوز در حالت آفلاین ممکن نیست؛ اعمال لغو در مشتری به همگام‌سازی بعدی وابسته است.
- این پیاده‌سازی هنوز سامانه ارسال ایمیل دعوت، گردش بازیابی مالک، چرخش کلید امضا، توزیع/همگام‌سازی خودکار مجوز به مشتری، پنل وب گرافیکی مالک یا پشتیبان‌گیری خارج از میزبان مرکز کنترل را تکمیل نکرده است.

**وضعیت:** کد پایه API مرکز کنترل و قالب استقرار در شاخه توسعه قرار دارد؛ تا زمانی که secretهای واقعی از مسیر امن تنظیم و آزمون end-to-end انجام نشود، مرکز کنترل فعال تولیدی محسوب نمی‌شود.
