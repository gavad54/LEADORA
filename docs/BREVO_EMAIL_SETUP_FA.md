# راه‌اندازی ایمیل تراکنشی LEADORA با Brevo

این راهنما برای اتصال ایمیل‌های سیستمی (مانند کد تأیید حساب و هشدارهای امنیتی) است؛ برای خبرنامه یا تبلیغات استفاده نشود.

## ۱) پیش‌نیاز در Brevo
1. یک حساب Brevo تحت مالکیت/مدیریت مجاز سازمان ایجاد یا استفاده کنید.
2. دامنه فرستنده را در Brevo اضافه و مالکیت آن را تأیید کنید.
3. رکوردهای DNS اعلام‌شده توسط Brevo را در DNS همان دامنه ثبت کنید؛ به‌ویژه SPF و DKIM. وضعیت احراز دامنه را در پنل Brevo بررسی کنید.
4. یک Sender از همان دامنه بسازید و تأیید کنید.
5. از بخش API Keys یک کلید API بسازید. کلید را در مخزن GitHub، کد، Issue، چت یا فایل مستندات قرار ندهید.

مستند رسمی ارسال ایمیل: https://developers.brevo.com/docs/send-a-transactional-email

## ۲) تنظیمات امن Railway
در سرویس Production فقط این متغیرها را ایجاد کنید؛ مقدارها را در چت ارسال نکنید:

| نام متغیر | مقدار |
|---|---|
| `BREVO_API_KEY` | کلید API ساخته‌شده در Brevo |
| `BREVO_SENDER_EMAIL` | ایمیل Sender تأییدشده روی دامنه شما |
| `BREVO_SENDER_NAME` | `LEADORA` |

پس از ذخیره متغیرها، Railway ممکن است Deployment جدید ایجاد کند. پیش از هر استقرار Production، وضعیت Backup/Restore و دروازه‌های انتشار LEADORA باید رعایت شوند. در این مرحله هیچ Deployment یا تغییری در Production انجام نشده است.

## ۳) آزمون اتصال
پس از استقرار نسخه دارای این قابلیت و تنظیم متغیرها:
- با حساب مالک وارد شوید.
- به `/api/platform/email/status` درخواست بزنید؛ این مسیر فقط وضعیت کلی تنظیمات را نشان می‌دهد و کلید یا مقدار متغیرها را برنمی‌گرداند.
- `POST /api/platform/email/test` یک ایمیل آزمایشی فقط به ایمیل حساب مالک واردشده می‌فرستد؛ گیرنده دلخواه از درخواست پذیرفته نمی‌شود.
- پاسخ موفق API به معنی پذیرفته‌شدن پیام توسط Brevo است، نه تضمین رسیدن به Inbox. تحویل نهایی باید در Transactional Logs بررسی شود.

## ۴) مرزهای امنیتی
- API Key فقط در Railway Variables نگهداری می‌شود.
- زمان انتظار درخواست محدود است و خطاهای سرویس بدون افشای پاسخ خام یا کلید API گزارش می‌شوند.
- Endpoint آزمایشی فقط برای مالک پلتفرم است و فقط به ایمیل همان حساب ارسال می‌کند.
- ارسال موفق پیام آزمایشی به‌تنهایی به معنی فعال‌شدن OTP یا تکمیل انتقال مالکیت نیست.


## ۵) انتقال مالکیت با تأیید دوطرفه ایمیلی

پس از استقرار نسخه‌ای که مسیر انتقال مالکیت را دارد:
1. مالک فعلی وارد حساب شود و صفحه `/platform-owner` را باز کند.
2. ایمیل حساب مقصد را وارد و درخواست انتقال را ثبت کند.
3. دو ایمیل مستقل ارسال می‌شود؛ یکی به مالک فعلی و دیگری به حساب مقصد. هر کد فقط ۱۰ دقیقه اعتبار دارد.
4. مالک فعلی، شناسه درخواست و کد دریافتی خودش را در فرم «تأیید ایمیل مالک فعلی» وارد کند.
5. مالک جدید باید با همان حسابی که ایمیل دعوت به آن ارسال شده وارد شود و شناسه درخواست و کد خودش را در فرم «پذیرش انتقال مالکیت» وارد کند.
6. مالکیت فقط پس از تأیید هر دو کد و در یک تراکنش اتمیک تغییر می‌کند. نشست‌های قبلی مالک قبلی باطل می‌شوند.

محدودیت‌ها:
- بین درخواست‌های انتقال مالکیت از یک حساب حداقل پنج دقیقه فاصله لازم است.
- هر کد حداکثر پنج بار قابل آزمون است؛ درخواست پس از ۱۰ دقیقه منقضی می‌شود.
- اگر ارسال یکی از دو ایمیل شکست بخورد، درخواست لغو می‌شود و مالکیت تغییر نمی‌کند.
- کدها در پایگاه داده فقط به‌صورت HMAC نگهداری می‌شوند؛ در پاسخ API یا گزارش ممیزی برگردانده نمی‌شوند.
- تأیید کد، کنترل دسترسی به صندوق ایمیل را در همان لحظه اثبات می‌کند؛ برای ادعای «ایمیل تأییدشده دائمی» باید سامانه مستقل email verification حساب نیز اجرا شود.
- این قابلیت تا زمان Merge کنترل‌شده، تنظیم Brevo، استقرار و آزمون واقعی در Production فعال نیست.
