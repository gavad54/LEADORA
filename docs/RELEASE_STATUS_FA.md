## قابلیت‌های موجود در مخزن
- ثبت‌نام/ورود، حساب شرکت و ساختار tenant
- ماژول‌های وب فارسی شامل داشبورد، مالی، پخش، مرکز فرمان AI و قیمت‌گذاری ماژولار
- مدیریت پایه محصولات و مشتریان و تعدادی جریان فروش/فاکتور/عملیات
- ماژول مشارکت مالی با ورودی دستی، CSV و چارچوب اتصال یکپارچه
- فایل‌های PWA و workflow ساخت اندروید
- تست‌های Python و CI برای آزمون‌ها و بررسی‌های ساختاری

وجود route یا صفحه به‌تنهایی اثبات‌کننده تکمیل end-to-end، امنیت یا آمادگی استفاده واقعی نیست.

## اصلاحات تأییدشده در آخرین انتشار
- رفع مسیرهای API تکراری و حذف تعریف‌های قدیمی ناسازگار با schema فعال.
- همسان‌سازی چرخه عمر اقدام‌های عامل با وضعیت‌های واقعی پایگاه داده و الزام تأیید پیش از تکمیل.
- اصلاح قالب‌های CSV، افزودن قالب کمپین، و اعتبارسنجی تاریخ و ارجاع مشتری در ورود فرصت‌ها.
- افزودن آزمون رگرسیون؛ کل CI شاخه اصلاحی سبز شد و deployment جدید با healthcheck موفق است.

## محدودیت‌ها و موانع باز
- مقادیر secretهای Railway در اتصال فعلی قابل مشاهده نیستند؛ صحت و چرخش آن‌ها باید در پنل امن بررسی شود.
- سیاست‌های امنیتی موجود اعلام می‌کند بازیابی رمز، تأیید ایمیل، MFA، ابطال نشست و نقش‌های ریزدانه کامل نیستند یا تأیید نشده‌اند.
- موفقیت پشتیبان‌گیری خارج از میزبان و آزمون بازیابی (restore) هنوز مدرک ندارد.
- درگاه پرداخت در API عمومی قیمت‌گذاری غیرفعال است؛ دریافت وجه آنلاین فعال فرض نشود.
- اتصال زنده به providerهای بیرونی، از جمله نقشه/CRM، فقط پس از پیکربندی و آزمون واقعی قابل اعلام است.
- تحلیل هوشمند موجود را نباید بدون شواهد مدل و اعتبارسنجی به‌عنوان AI پیش‌بینی‌گر تأییدشده معرفی کرد.
- workflow اندروید و وجود سورس به معنی APK نهایی امضاشده، نصب‌شده و تأییدشده فروشگاه نیست.
- بازبینی مستقل امنیتی، حریم خصوصی و حقوقی انجام‌شده فرض نمی‌شود.

## معیارهای لازم پیش از استفاده تجاری با داده واقعی
1. اجرای کامل آزمون‌ها و افزودن آزمون‌های رگرسیون برای هر اصلاح.
2. آزمون جداسازی tenant برای همه منابع و مسیرها، شامل گزارش‌ها و مشارکت مالی.
3. آزمون مثبت/منفی احراز هویت مالک و دسترسی مدیریتی.
4. تطبیق مستقل فرمول‌های مالی و آزمون وضعیت‌های تأیید، اختلاف، اصلاح و تسویه.
5. بکاپ زمان‌بندی‌شده، نسخه خارج از volume و آزمون restore روی محیط جداگانه.
6. آزمون موبایل واقعی، PWA، رفتار شبکه ضعیف و جریان‌های اصلی.
7. بررسی وابستگی‌ها، امنیت، حریم خصوصی، retention و برنامه پاسخ به رخداد.
8. آزمون تولید کنترل‌شده، مستندسازی rollback و نسخه‌بندی.
9. برای انتشار Android: artifact واقعی، امضای release امن، آزمون نصب و رعایت الزامات فروشگاه.

## راه‌اندازی توسعه
Python 3.12+:
```bash
pip install -r requirements.txt
uvicorn app.main:app --host 127.0.0.1 --port 8000
```

برای production، `LEADORA_ENV=production`، یک `LEADORA_SECRET` تصادفی و امن حداقل 32 نویسه و `LEADORA_DB=/data/leadora.db` را در تنظیمات امن میزبان تأیید کنید. secretها را در مخزن یا گزارش عمومی قرار ندهید.
