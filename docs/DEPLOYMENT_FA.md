# راهنمای راه‌اندازی و انتشار LEADORA

## اجرای آزمایشی محلی
1. Python 3.12+ نصب کنید.
2. در پوشه مخزن اجرا کنید: `pip install -r requirements.txt`
3. یک مقدار تصادفی امن برای `LEADORA_SECRET` تنظیم کنید؛ برای حالت production حداقل ۳۲ نویسه باشد.
4. اجرا: `uvicorn app.main:app --host 127.0.0.1 --port 8000`
5. در مرورگر `http://127.0.0.1:8000` و سپس `/api/health` را بررسی کنید.

## Docker
با تنظیم `LEADORA_SECRET` در محیط، اجرا کنید: `docker compose up --build -d`. فایل `compose.yaml` عمداً بدون secret از فایل نمونه اجرا نمی‌شود. Dockerfile اکنون متغیر `PORT` میزبان را می‌خواند و برای اجرای محلی به‌طور پیش‌فرض از پورت 8000 استفاده می‌کند.

## نصب روی گوشی و کامپیوتر
رابط وب واکنش‌گراست و فایل‌های پایه PWA (`manifest.webmanifest`، `service-worker.js` و `icon.svg`) دارد. برای فعال‌شدن نصب از مرورگر باید برنامه با HTTPS منتشر شود. پس از انتشار، در Chrome اندروید از منو گزینه «افزودن به صفحه اصلی / Install app» را انتخاب کنید؛ در کامپیوتر Chrome/Edge از دکمه نصب یا منوی مرورگر استفاده کنید. قابلیت نصب باید روی دستگاه‌های هدف جداگانه آزموده شود. این مرحله به‌تنهایی فایل APK یا نصاب مستقل ویندوز نمی‌سازد.

## انتشار روی Render (جایگزین Railway)

مخزن دارای فایل Blueprint به نام `render.yaml` است: [مشاهده فایل](https://github.com/gavad54/LEADORA/blob/main/render.yaml). این فایل پیکربندی است و به‌تنهایی سرویس آنلاین ایجاد نمی‌کند.

1. در پنل Render وارد شوید و **New → Blueprint** را انتخاب کنید.
2. مخزن `gavad54/LEADORA` و شاخه `main` را متصل و Blueprint را بررسی کنید.
3. پیش از ایجاد سرویس، هزینه پلن `Starter` و دیسک پایدار را در پنل بررسی کنید؛ این تنظیم رایگان فرض نمی‌شود.
4. Blueprint متغیر `LEADORA_SECRET` را تولید می‌کند و `LEADORA_ENV=production` و `LEADORA_DB=/data/leadora.db` را تنظیم می‌کند. مقدار secret را منتشر نکنید.
5. پس از ایجاد سرویس، منتظر پایان Build/Deploy بمانید و آدرس HTTPS تولیدشده را باز کنید. مسیر `/api/health` باید پاسخ موفق بدهد.
6. ثبت‌نام و ورود آزمایشی، ایجاد کالا/مشتری، جداسازی داده دو شرکت، restart و حفظ داده پس از restart را آزمایش کنید. تا پیش از این آزمون‌ها سرویس را آماده داده واقعی تلقی نکنید.

**نکته مهم:** من از داخل مخزن می‌توانم کد و Blueprint را آماده کنم، اما ایجاد سرویس در حساب Render، پذیرش هزینه‌ها و تأیید نهایی Deploy نیازمند دسترسی مجاز به پنل همان حساب است. وجود `render.yaml` به معنی آنلاین‌شدن برنامه نیست.

## انتشار روی Railway
مخزن از Dockerfile برای ساخت استفاده می‌کند. فایل `railway.json` مسیر بررسی سلامت `/api/health` را مشخص می‌کند و Dockerfile روی `0.0.0.0` و پورت تزریق‌شده توسط Railway گوش می‌دهد.

قبل از اولین انتشار، در بخش **Variables** سرویس این مقادیر را تنظیم کنید:
- `LEADORA_ENV` = `production`
- `LEADORA_SECRET` = یک مقدار تصادفی محرمانه با دست‌کم ۳۲ نویسه؛ آن را در مخزن Git یا پیام عمومی قرار ندهید.
- `LEADORA_DB` = `/data/leadora.db`

سپس یک **Volume** با مسیر اتصال `/data` بسازید تا پایگاه داده SQLite بعد از استقرار مجدد حفظ شود. پس از تنظیم متغیرها و Volume، Deploy را اجرا کنید و در لاگ‌ها بررسی کنید که برنامه شروع شده و `/api/health` پاسخ موفق می‌دهد. اگر `LEADORA_SECRET` تنظیم نشده باشد، اجرای حالت production عمداً متوقف می‌شود.

## انتشار روی میزبان دیگر
1. یک سرویس وب Python/Docker در میزبان مورداعتماد بسازید و مخزن `gavad54/LEADORA` و شاخه `main` را متصل کنید.
2. دستور اجرا: `uvicorn app.main:app --host 0.0.0.0 --port $PORT` یا دستور متناظر میزبان.
3. متغیرهای `LEADORA_ENV=production`، `LEADORA_SECRET` تصادفی و `LEADORA_DB` روی مسیر پایدار تنظیم کنید.
4. اگر SQLite استفاده می‌شود، فعال‌کردن فضای ذخیره‌سازی پایدار و پشتیبان‌گیری الزامی است. دیسک موقت یا ephemeral باعث از دست‌رفتن داده‌ها می‌شود.
5. مسیر بررسی سلامت `/api/health` است. HTTPS، لاگ‌ها، بکاپ و بازیابی را آزمایش کنید.

**وضعیت:** اصلاح تنظیمات مخزن به‌تنهایی به معنی انتشار موفق نیست؛ متغیرهای محرمانه، Volume و نتیجه Deploy باید در پنل میزبان تأیید شوند. تا پایان بررسی امنیتی، از داده واقعی مشتری استفاده نکنید.
